02 · Domain Model

One universal model carries history, science, products, culture, and the future: entities, claims, properties, relationships, geometry, sources. No per-category schemas.

Core concepts

DM-1The universal entityMVP

Anything that has a time, a place, measurable properties, or relationships to other things can be an entity. The complete conceptual reduction:

ENTITY
  ├── existed during TIME        (temporal claim, DM-4)
  ├── existed at PLACE           (geometry, DM-7)
  ├── has PROPERTY               (property value, DM-6)
  ├── has CLAIM                  (sourced statement, DM-5)
  ├── related to ENTITY          (relationship, DM-8)
  └── supported by SOURCE        (provenance, DM-9)

Entity types are an extensible enum, not table-per-type. Initial set: event, person, species, object, place, organization, state, civilization, idea, theory, discovery, invention, patent, paper, book, artwork, film, game, product, technology, standard, law, religion, language, disease, chemical, material, structure, astronomical_object, natural_event, future_event, record, time_series. Unknown types must be an ingestion error, not silently coerced (fail loud).

DM-2Relational schema, not a graph databaseMVP

PostgreSQL + PostGIS. Graph traversals are modeled with indexed relational tables; a graph DB is considered only if traversal load ever dominates (it will not for MVP). Core tables:

entity
  id              bigint PK
  slug            text UNIQUE            -- URL identity: 'tyrannosaurus-rex'
  type            entity_type NOT NULL
  name            text NOT NULL
  description     text                   -- our own short text, not copied Wikipedia prose
  start_time      timeline_time          -- denormalized best-consensus (see DM-4)
  end_time        timeline_time
  time_precision  time_precision
  temporal_status temporal_status        -- observed .. speculative (DM-4)
  categories      category[]             -- topic facets for filtering
  importance      jsonb                  -- precomputed vector (see 07 ZOOM-2)
  bucket_min      smallint               -- first time bucket where it renders (T0..T13)
  bucket_max      smallint
  wikidata_id     text                   -- Qxxxx when applicable
  wikipedia_url   text
  created_at / updated_at

relationship
  id, source_entity, relationship_type, target_entity,
  valid_from, valid_until, source_id, confidence

claim            -- DM-5
property_value   -- DM-6
geometry_record  -- DM-7
source           -- DM-9
media_ref        -- DM-10
slug_alias       -- DM-2a: (old_slug PK, entity_id FK)
DM-2aSlug policyMVP

Slugs are the public, permanent identity of an entity (API-5). Rules:

  • Generation: lowercase ASCII kebab-case derived from the English name: Unicode-transliterate, strip punctuation, collapse whitespace/hyphens, trim to 80 chars. Tyrannosaurus rex → tyrannosaurus-rex.
  • Collision resolution, deterministic: first claimant (highest importance in the import batch) keeps the bare slug; others append, in order of preference: start year (battle-of-lechfeld-955), then entity type (mercury-planet vs mercury-element), then as final fallback the Wikidata id (-q308). Same dump + same code must yield the same slugs (required for reproducible imports, SRC-3).
  • Permanence: a published slug is never reassigned to a different entity, ever. Renames mint a new slug and insert the old one into slug_alias; aliased slugs answer with HTTP 301 to the canonical URL. Deleting an entity retires its slug permanently (alias to nothing is a 410, not a reuse).
DM-3Event hierarchyMVP

Events nest via part_of relationships: WWII → European theatre → Eastern Front → Battle of Stalingrad → individual assaults. Zoom level determines which level of the tree renders (see 07). The hierarchy is plain relationships, not a separate tree table.

Time

DM-4Temporal model: arbitrary precision + uncertainty statusMVP

The timeline spans >100 orders of magnitude, far outside timestamptz range. Represent time as a custom composite:

timeline_time {
    -- seconds relative to epoch 1970, stored as UNCONSTRAINED numeric.
    -- numeric(40,6) would top out near 1e34 s (~3e26 years): too small for
    -- the ~3e107 s heat-death horizon. Unconstrained numeric has no such cap.
    t          numeric
}

time_precision: billion_year | million_year | millennium | century |
                decade | year | month | day | hour | minute | second

temporal_status:
  observed         -- Apollo 11 landing, measured
  documented       -- contemporary records
  estimated        -- T. rex 68-66 Ma; reconstructed dates
  projected        -- Sun red giant ~5 Ga (model, high confidence)
  model_dependent  -- heat death (depends on cosmological model)
  speculative      -- human Mars settlement
  legendary        -- founding of Rome 753 BCE (traditional date)
  disputed         -- competing scholarship

Every temporal statement is a TemporalClaim { time, uncertainty_range, status, confidence, sources[] }. The denormalized entity.start_time/end_time is the current synthesis for fast queries; the claims remain the ground truth. Rendering rules per status are in FE-7.

Wikidata stores at most day precision. Sub-day sequences (JFK motorcade minute by minute, D-Day hours) come from Wikipedia/LLM extraction with retained source paragraph + confidence (see SRC-4). The schema must accept second precision from day one.
DM-5Claims, not truthsMVP

The single most important design decision. Contributors and importers submit claims; conflicting claims coexist; the display shows the synthesis with its spread, never a fake exact value ("Rome, 100 CE: estimated 500k–1M", not "873,422").

claim
  id            bigint PK
  entity_id     bigint FK
  property      text          -- 'max_speed', 'population', 'date_of_battle'
  value         jsonb         -- typed value, range, or geometry ref
  unit          text          -- UCUM code where applicable
  min / max     numeric       -- uncertainty range
  value_type    enum: measured | estimated | reconstructed | projected
  method        text          -- 'biomechanical simulation'
  source_id     bigint FK     -- required (DM-9)
  published_at  date          -- when this claim was made: REQUIRED, powers
                              -- the knowledge-date slider (VIS-6)
  confidence    real          -- 0..1
  superseded_by bigint        -- nullable; claims are never deleted
  status        enum: active | disputed | retracted

Example: T. rex max_speed has one claim of 18–25 km/h (paper A, 2017, biomechanical simulation) and one of 20–30 km/h (paper B, 2024); the entity surface shows "likely 18–30 km/h, 2 estimates". A claim being wrong is handled by superseded_by/retracted, never by deletion: the history of knowledge is itself product content.

Properties and measurements

DM-6Property values with units, validity dates, uncertaintyMVP

Properties are the comparison engine (T. rex vs. elephant; Concorde vs. SR-71). Never a bare number:

property_value
  entity_id, property, value, unit,
  min, max,
  valid_from, valid_until,     -- a country's population is time-dependent
  value_type,                  -- measured vs estimated changes rendering
  source_id, method, confidence

Property names come from a registry table (property_def: name, datatype, canonical_unit, description); unknown property names are an ingestion error. Unit conversion happens at read time from canonical units. Time-series data (world population, CO₂, transistor counts) uses the same table with dense valid_from points, or Parquet side-files for large series (SRC-8).

Geometry

DM-7Time-aware geometry with explicit representation typeMVP
geometry_record
  id, entity_id
  geom            geometry(GEOMETRY, 4326)   -- point/line/polygon/multi*
  valid_from, valid_until                    -- timeline_time
  representation  enum:
      exact              -- surveyed/treaty borders, buildings, railways
      administrative     -- official but idealized
      estimated          -- scholarly reconstruction
      fuzzy              -- languages, cultures, religions, influence
      point_distribution -- philosophy schools, fossil finds: points, not areas
  confidence      real
  source_id       bigint FK
  reconstruction  text      -- label when multiple competing reconstructions exist
  • An entity may have many geometry records over time (Roman Empire borders per period) and several competing reconstructions for the same period (disputed borders); the map can switch between them.
  • fuzzy and point_distribution must render visibly differently from exact (heat/intensity, dotted edges): never imply that "Occitan-speaking area, 1300" is a treaty border. A language layer stores LanguageRegion { language, geom, valid_from, valid_to, confidence, sources }, not "France → French".
  • GiST index on geom; btree on (valid_from, valid_until); combined queries are the hot path (API-1).
  • Deep-time paleogeography (Pangaea, coastlines) is a separate basemap tile set selected by time range, not per-entity geometry (FE-5).

Relationships

DM-8Typed relationship vocabularyMVP

Closed, extensible enum; unknown types are ingestion errors. Initial vocabulary:

part_of          caused_by        resulted_in      invented_by
based_on         built_upon       replaced         influenced
influenced_by    occurred_at      participant      contemporary_with
spread_to        disproved_by     confirmed_by     discovered_by
used_by          created_by       preceded         succeeded
supports         parent_taxon     depicts          about

Relationships may carry valid_from/valid_until, source_id, and confidence. The V2 graph view (VIS-7) and "what enabled this?" queries traverse these; MVP populates them from Wikidata properties (P361 part of, P828 has cause, P1542 has effect, P710 participant, P61 discoverer, etc.).

Provenance and media

DM-9Source records; provenance is never discardedMVP
source
  id, kind        enum: wikidata | wikipedia | ohm | commons | youtube |
                        openalex | crossref | patent_office | dataset |
                        book | primary_document | user | organization
  external_id     text       -- Qxxxx, DOI, patent no, OHM id, video id
  url, title, author
  license         text       -- SPDX-like: 'CC0-1.0', 'CC-BY-SA-4.0'
  attribution     text       -- ready-to-render attribution string
  retrieved_at    timestamptz

Every claim, geometry record, property value, and media reference has a source_id. License drives automatic attribution rendering and lets the pipeline exclude records whose terms we do not accept (SRC-2).

DM-10Media by reference onlyMVP
media_ref
  entity_id, kind  enum: image | video | audio | map_scan | document
  commons_id / youtube_id / external_url
  thumbnail_url, license, author, attribution, source_url
  quality_score, language, duration_s
  audience         enum: general | kids | academic | quick   -- V2 voting refines

We store identifiers and metadata; bytes stay at Wikimedia/YouTube. Videos are curated/ranked per entity, not live-searched at view time.

Worked example

Battle of Waterloo (entity: event)
  slug: battle-of-waterloo, wikidata: Q48314
  temporal: 1815-06-18, precision=day, status=documented
  part_of -> Napoleonic Wars -> War of the Seventh Coalition
  participant -> France, United Kingdom, Prussia, Napoleon, Wellington
  geometry: battlefield polygon (representation=estimated, source=OHM)
  claims:
    troops_france = 73,000   (source: X, confidence 0.7)
    troops_france = 77,500   (source: Y, confidence 0.6)   -- coexists
  media: Commons paintings (license per file), 3 ranked YouTube docs
  importance: global 0.97 -> renders from bucket T7 (millennium view) down

Explicitly out of the schema (YAGNI)

  • No multilingual content tables in MVP (English first; name_i18n jsonb reserved, unused).
  • No embeddings/vector columns until 08 shows a need.
  • No user/reputation tables until 09 ships; but nothing in this schema may assume single-writer truth (claims model guarantees that).
