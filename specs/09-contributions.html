09 · Contributions & Community

Model: GitHub + Wikipedia + OpenStreetMap, not "everyone edits the database." Users submit claims, corrections, sources, and datasets; validators check them; trusted contributors review; every change has provenance. All of this is post-MVP, but the claims model (DM-5) exists from day one precisely so this can bolt on without a rewrite.

Scope note: nothing in this document blocks MVP. The MVP obligations are only: claims with sources and published_at (DM-5), no single-writer truth assumptions, git-like audit fields on mutations, and the open-data decision (CONTRIB-8).

Contribution model

CONTRIB-1Users contribute claims, not truthV2

A submission is a claim with source, method, and uncertainty; it coexists with competing claims rather than overwriting a field. Works identically for science (T. rex speed estimates per paper) and history (population of Rome per source). Edit wars become parallel sourced claims plus a synthesis, and genuine scholarly disagreement (Hannibal's route, causes of Rome's fall) is stored as alternative interpretations with evidence, each with supporters and sources. Disputed borders store multiple reconstructions the map can switch between (DM-7).

CONTRIB-2Contribution types and review routesV2
ContributionDifficultyReview route
Fix a date / add coordinates / add a source / add a patent linkEasyAutomated validation + source check; machine-verifiable sources (DOI metadata, patent office records, election results) auto-accept
Add event/person, add measurement, add relationship, challenge a claim, add uncertaintyMediumCommunity review, source required

Contribution UI is embedded in normal browsing (small "add source / suggest correction / add media" actions on every entity, click-a-date-to-propose), plus a map editing mode for local history (select "Berlin 1925" → add building/road/business/photo with source, OSM-style). No giant "EDIT DATABASE" button.

CONTRIB-3Automated validator pipelineV2
submission → schema validation → source validation → duplicate detection
           → consistency checks (dates, geography, outliers)
           → AI anomaly assist (assistant, never the authority)
           → routed to human review queue by type + domain

Reuses the ingestion validation gates (03): "Napoleon born 1969" and "battle in Germany, coords in Brazil" never reach a human.

Trust

CONTRIB-4Domain-specific reputationV2

Reputation is a vector, not a scalar: 5,000 great WWII edits confer no paleontology authority. Reviews of a claim are weighted by the reviewer's reputation in that claim's domain. Verified experts (e.g. a university paleontologist) can receive domain roles without cross-domain authority. Contributor ladder: visitor → contributor → trusted → reviewer → domain reviewer → maintainer; privileges accrue slowly (propose → approve simple → review disputed → schema/source issues).

CONTRIB-5Transparency: history, revert, credit, followV2

Every entity has public git-like history (what changed, why, source, contributor, diff view) and cheap revert. Contributors get visible credit per entity ("History · Contributors · Sources") and profiles with acceptance stats and specialties; dataset contributions keep attribution ("Roman roads of Dacia - C.M., 2026"). Users can follow entities/topics and are notified of proposed changes, creating distributed volunteer review. Badges represent verified work (1,000 verified locations), never engagement.

CONTRIB-6Microtasks and crowd rankingV2

Game-like small tasks: "was this event in Paris or Versailles?", "same person?", "best image?", "drop a pin". Importance ranking uses pairwise comparisons ("which is more historically important?") aggregated Elo-style, contextual by scope (global / to aviation / to Germany), feeding ZOOM-2. Uncertainty is voted on by qualified contributors as "which estimates are credible", never "what is the true number".

Institutions

CONTRIB-7Bulk imports and organization accountsV2

The main growth channel: a researcher uploads 47k archaeological sites as CSV/GeoJSON/Parquet, maps their columns to our schema in a preview UI (new entities / likely duplicates / invalid rows), and a maintainer approves the batch. Verified organization accounts (museums, universities, archives, patent offices) publish datasets under their identity with license metadata. Incentives: museums get "see this object at Museum X" backlinks; researchers claim their papers and link them to the claims they support; classrooms contribute through a teacher-reviewed sandbox. One good dataset outweighs years of manual edits.

The open-data decision

CONTRIB-8Community data is openMVP (decision)

Decided now, before any contributor exists: the community-contributed knowledge graph (or a very large core of it) is open under a clear license. Nobody spends weekends enriching a proprietary database. The company monetizes the application, hosting, AI, education, collaboration, analysis, and API capacity - not ownership of contributed facts. Long-term structural option: open data foundation + commercial app company. This commitment appears in the public data policy from first launch.
