08 · Search & AI

Search is how most sessions start. Most "AI-like" questions are database queries; the LLM's job is translating language into structured queries and explaining results - not answering every interaction.

Entity search

SRCH-1MVP search: PostgreSQL full-text + trigramMVP
  • Typical queries: "T rex", "Battle of Berlin", "Roman Empire", "invention of radio". Instant search-as-you-type over entity names + aliases + short descriptions.
  • Implementation: tsvector + pg_trgm GIN indexes; ranking blends text score with importance.global so "Rome" surfaces the empire before minor namesakes.
  • Aliases table populated from Wikidata labels/aliases (multilingual aliases accepted even though the UI is English-only, so "Rom", "Roma" resolve).
  • Result action: selecting a result focuses timeline + map + inspector on the entity (not a page navigation).
  • p95 < 50 ms at origin. Move to OpenSearch/Meilisearch only when measured quality/latency demands it (LATER).

Structured question compilation

SRCH-2Query templates before LLMsV2

Many valuable questions compile to SQL with no model at all. Ship a template library with typed slots (entity, time range, place, category, property):

"Which dinosaurs lived at the same time as {X}?"
    → overlap(species.start, species.end, X.start, X.end)
"What wars were happening when {person} was {age}?"
    → time window from birth+age, category=war
"Fastest {product_type} in {year}?"
    → property_value max_speed where valid_from <= year
"Inventions from {country} between {y1} and {y2}"
"What existed together?" / contemporaries    → API-2 sub-resource

The search box detects template matches (rule-based parse first); each template renders as a real view with a shareable URL. This is also the SEO page generator's vocabulary.

SRCH-3Natural-language questions ("Ask")V2
user question
   → cheap intent classifier / template matcher      (no LLM or tiny model)
   → if template match: execute structured query, render view
   → else: small LLM converts to structured query plan against the
     schema (entities, relationships, properties, time, place)
   → execute; LLM writes a short explanation OVER RETRIEVED FACTS ONLY,
     with entity links; every numeric statement must cite a claim id
   → large model reserved for multi-hop questions that fail the above

Answers must be grounded: the model never asserts facts that are not in the retrieved result set. "Ask about current view" passes the viewport state as context.

Cost policy

SRCH-4AI cost fenceMVP (policy)

Naive LLM-per-interaction at 1M MAU ≈ $100k/month and would dwarf all infrastructure. Binding rules:

  • Search, map, timeline, entity browsing, comparisons: never require a model call.
  • Escalation ladder is mandatory: template → small model → large model; each step logged with cost attribution; conversion rates between steps on the ops dashboard.
  • NL answers for common questions are cached by normalized question + dataset version.
  • Free tier gets a metered number of AI questions; Pro raises the cap. Hard monthly budget alarm; the feature degrades to template-only rather than overspending (with an explicit user-facing message, not a silent downgrade).

SEO surface

SRCH-5Long-tail landing pagesV2

Every entity page is crawlable from MVP (API-6). V2 adds generated intersection pages from the snapshot job: /time/1945/berlin, /inventions/19th-century, /dinosaurs/cretaceous, /cars/fastest/1970s. Pages are static-rendered from precomputed data (no per-crawl compute), interlinked, and each carries the interactive app as progressive enhancement. Organic search is the primary acquisition channel; these pages are the funnel.
